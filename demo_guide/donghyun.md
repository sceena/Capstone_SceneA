# 👤 멘티 - 강동현 데모 가이드

## 1. 📄 채용공고 정보
* **공고명**: 초실시간 양방향 통신 백엔드 개발자
* **업무 자격요건**:
  * Node.js 및 NestJS 기반 백엔드 애플리케이션 개발 역량
  * WebSocket, Socket.io 등을 활용한 양방향 실시간 웹 통신 구현 경험
  * RDBMS(PostgreSQL 등) 설계 및 데이터 트랜잭션 관리 기본 지식
  * 네트워크 프로토콜(TCP/IP, HTTP) 및 패킷 전송 원리에 대한 이해
* **인재상**:
  * 실시간 동기화 오류 및 딜레이 상황에 신속히 대처하는 기민형 인재
  * 네트워크 패킷 및 오버헤드 최적화의 디테일을 고집하는 정밀형 인재
  * 프론트엔드 실시간 클라이언트와의 요구사항을 긴밀하게 조율하는 소통형 인재
* **우대사항**:
  * 다중 Node.js 인스턴스 분산을 위한 Redis Pub/Sub 또는 Socket.io 클러스터링 구축 경험
  * Jest 등을 활용한 실시간 비동기 소켓 이벤트 테스트 코드 작성 경험
  * 소켓 단선 상황에서의 재접속 핸드셰이크 및 세션 복구 아키텍처 설계 경험자

## 2. 📝 자기소개서 내용

### [지원동기]
저는 다수의 사용자가 동시에 참여하여 실시간으로 소통할 수 있는 양방향 미디어 및 데이터 통신 아키텍처 구현에 큰 매력을 느낍니다. 학과 캡스톤 디자인 프로젝트로 실시간 다인용 화이트보드 협업 툴을 개발하면서, 여러 사용자가 동시에 캔버스를 그릴 때 발생하는 메시지 순서 꼬임과 실시간 동기화 지연 현상을 목격했습니다. 클라이언트 간의 네트워크 레이턴시를 최소화하고, 서버의 리소스를 효율적으로 분배하여 끊김 없는 상호작용을 보장하는 기술이 웹 서비스의 사용자 경험을 극대화한다는 것을 확인했습니다. 귀사는 모의 면접 화상 통신과 실시간 면접 평가 분석을 결합하여, 공간의 제약 없이 고품질의 실시간 면접 시뮬레이션을 가능하게 하는 서비스를 선도적으로 개발하고 있습니다. 제가 실시간 통신 환경에서 쌓아온 소켓 분산 처리 및 미디어 서버에 대한 지식을 귀사의 서비스에 접목하여, 대규모 그룹 면접에서도 끊김이나 딜레이 없이 완벽한 몰입감을 선사하는 초실시간 양방향 면접 환경을 구현하고 싶습니다.

### [본인의 강점과 약점]
저의 큰 기술적 강점은 네트워크 프로토콜과 패킷 흐름에 대한 깊은 이해를 바탕으로 실시간 병목 구간을 빠르게 진단해 내는 능력입니다. WebSocket 통신에서 발생하는 프레임 유실이나 패킷 지연을 Wireshark나 Chrome DevTools로 실시간 추적하고, 효율적인 바이너리 직렬화 포맷을 도입해 전송 오버헤드를 낮추는 등의 네트워크 최적화 작업을 즐깁니다. 반면, 저의 약점은 실시간 통신 기능의 즉각적인 구현에 집중하다 보니 데이터의 장기적인 영속성 보장이나 관계형 데이터베이스(RDB)의 엄격한 스키마 설계 및 데이터 관리 지식에서 상대적인 깊이가 조금 부족하다는 점입니다. 이러한 단점을 보완하기 위해 프로젝트 진행 시 RDB의 트랜잭션 격리 수준(Isolation Level)과 관계형 데이터 모델링 규칙을 의도적으로 학습하고 있습니다. 최근에는 채팅 이력 데이터를 PostgreSQL에 안전하게 저장하기 위해 Write-Ahead Logging(WAL) 구조와 인덱스 스캔 방식을 깊이 스터디하여 데이터 정합성 보장 역량을 다각도로 넓혀가고 있습니다.

### [실무/프로젝트 문제 해결 경험]
NestJS와 Socket.io를 사용하여 다수의 사용자가 동시에 참여하는 실시간 다인용 화상 모의 면접 룸의 이벤트 동기화 서버를 구축하고 성능을 개선한 프로젝트 경험이 있습니다. 초기에는 단일 인스턴스 서버로 구축했으나, 면접 룸의 개수와 참여자 수가 일정 수준을 넘어서자 CPU 점유율이 90% 이상으로 치솟으며 클라이언트 소켓 연결이 빈번히 유실되고 메시지 전송이 지연되는 부하 현상이 일어났습니다. 저는 이 문제를 다중 서버 분산 아키텍처로 확장하여 해결했습니다. Nginx 로드밸런서를 전면에 배치하여 클라이언트 세션을 분배하고, 다중 NestJS 인스턴스 간의 소켓 메시지 동기화를 위해 Redis Pub/Sub을 브릿지로 연동했습니다. 특히 실시간 데이터 전송 오버헤드를 최소화하기 위해 JSON 형태의 무거운 메시지를 필요한 핵심 정보만 포함하는 커스텀 패킷 구조로 압축했습니다. 그 결과, 단일 서버의 메모리 부하를 약 40% 분산시켰으며, 동시 접속 사용자 수가 기존 한계치 대비 3.5배 증가한 환경에서도 메시지 레이턴시를 80ms 이내로 균일하게 안정화하는 성과를 도출했습니다.

* **답변**:
 > "네, 저는 실시간 소켓 통신을 효율적으로 다루기 위해서 Node.js 환경의 NestJS 프레임워크와 Socket.io 라이브러리를 사용했습니다. 스프링 부트 소켓도 알아봤지만 자바스크립트 기반이 프론트와의 연계도 잘 맞고 구현이 직관적이라고 보았습니다. 그리고 여러 서버를 띄울 경우 소켓 통신 메시지가 서로 교환이 안 될 수 있는 문제가 있어서, 인스턴스 간 브릿지로 Redis의 Pub/Sub을 연결하여 소켓 서버 간 메시지를 동기화하는 구조를 잡았습니다."

### ❓ [개인 질문 1 (추천 1번)]
* **질문**: "다중 NestJS 서버 인스턴스 환경에서 소켓 세션을 공유하기 위해 Redis Pub/Sub을 사용하셨는데, 특정 인스턴스 장애로 연결이 끊어졌을 때 클라이언트의 재접속 시나리오와 세션 복구 흐름은 어떻게 설계되어 있나요?"
* **답변**:
 > "서버가 다운되면 클라이언트에 띄워진 Socket.io 클라이언트 모듈이 자동으로 감지해서 재접속을 하도록 기본 동작을 활용했습니다. 이때 로드밸런서인 Nginx가 살아있는 다른 NestJS 인스턴스로 소켓을 균등하게 재연결해 주기 때문에, 각 인스턴스들이 Redis Pub/Sub 어댑터로 메시지를 공유하고 있어 멘티들은 연결이 끊겼던 방에 바로 복귀해 세션을 이어나갈 수 있게 구현했습니다."

### ❓ [개인 질문 2 (추가 질문)]
* **질문**: "실시간 채팅 중 네트워크 연결이 빈번하게 끊겼다 복구되는 불안정한 클라이언트 환경에서, 메시지 누락 없이 대화를 복구하는 재연결 정책과 메시지 시퀀스 넘버 관리 방안은 무엇인가요?"
* **답변**:
 > "네트워크 끊김으로 메시지 누락이 생기면 곤란하므로, 저는 소켓이 다시 연결되는 이벤트가 들어올 때 해당 룸의 모든 이전 대화 데이터를 데이터베이스 PostgreSQL에서 다시 SELECT 쿼리로 전체를 조회해서 클라이언트로 쫙 뿌려주는 방식을 사용했습니다. 시퀀스 넘버의 경우에는 아직 완벽히 구현하진 못했고, 그냥 데이터베이스 기본 키인 Auto Increment ID를 오름차순으로 정렬해서 클라이언트가 마지막으로 본 데이터가 무엇인지 순서만 비교해 렌더링하도록 짰습니다."
