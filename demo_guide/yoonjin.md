# 👤 멘티 - 정윤진 데모 가이드

## 1. 📄 채용공고 정보
* **공고명**: AI 파이프라인 서빙 백엔드 개발자
* **업무 자격요건**:
  * Python 및 FastAPI / Flask 기반의 백엔드 서비스 개발 역량
  * RDBMS(PostgreSQL 등)의 기본적인 설계 및 쿼리 튜닝 능력
  * 비동기 태스크 큐 프레임워크(Celery, asyncio)의 작동 방식 이해
  * 대용량 미디어 파일(오디오, 비디오) 처리 및 데이터 전처리 지식
* **인재상**:
  * 타 부서(AI 모델러, 기획자 등)와의 원활한 소통을 이끄는 협업형 인재
  * 신규 프레임워크 도입 전 안정성을 철저히 기하는 신중형 인재
  * 복잡한 파이프라인의 구조적 문제를 발견하고 혁신을 시도하는 개척자형 인재
* **우대사항**:
  * RabbitMQ, Redis Pub/Sub 등 메시지 브로커를 활용한 대기열 구축 경험
  * Docker, Alembic 등을 활용한 컨테이너 배포 및 마이그레이션 경험
  * 대용량 배치 처리 및 비동기 모델 병렬 처리 아키텍처 설계 경험자

## 2. 📝 자기소개서 내용

### [지원동기]
저는 대용량 원천 데이터로부터 유의미한 가치를 도출하고 이를 서비스화하는 AI 데이터 파이프라인 구축 분야에 큰 흥미를 느끼고 있습니다. 학부 연구생 시절, 공공 영상 데이터를 기반으로 객체를 탐지하고 분류하는 모델을 백엔드 서버에 서빙하는 프로젝트를 진행한 적이 있습니다. 당시 단일 요청 처리에는 문제가 없었으나, 수백 명의 사용자가 동시에 동영상을 업로드하자 모델의 긴 추론 속도로 인해 웹 서버 전체가 동결되는 장애를 경험했습니다. 이 일을 계기로 AI 모델의 우수성만큼이나 이를 안정적이고 효율적인 비동기 파이프라인으로 서빙하는 백엔드 아키텍처가 필수적임을 깨달았습니다. 귀사는 인공지능 기반의 면접 분석 피드백을 통해 멘티들의 역량을 정량화하여 제시하는 시장 선두의 기술력을 확보하고 있습니다. 모델의 응답 속도 지연을 줄이고, 다양한 원천 데이터를 실시간으로 수집하고 정제하여 대규모 AI 분석 연산을 안정적으로 배포하는 파이프라인 아키텍처를 직접 설계하고 최적화하고 싶어 지원하게 되었습니다.

### [본인의 강점과 약점]
저의 큰 강점은 기획자나 데이터 사이언티스트와의 적극적인 소통을 통해 기술 요구사항을 명확히 명세화하고 조율하는 협업 능력입니다. AI 서빙 파이프라인을 다룰 때는 백엔드 개발자 혼자만의 생각보다 모델을 만든 사이언티스트와의 데이터 포맷 싱크와 리소스 한계 설정이 매우 중요하기 때문에, 적극적인 피드백을 통해 중간 조율자 역할을 성실히 수행합니다. 반면, 약점은 새로운 AI 기술 트렌드와 분산 프레임워크를 빠르게 도입하려는 의욕이 앞선 나머지, 기존 아키텍처와의 통합 테스트나 호환성 검증 프로세스를 가끔 성급하게 진행하는 면이 있다는 점입니다. 이를 보완하기 위해 신규 기술이나 라이브러리를 실제 프로젝트에 도입하기 전에, 반드시 별도의 샌드박스 개발 격리 환경을 구축하여 호환성 및 부하 테스트를 선행하도록 규칙을 정했습니다. 테스트 결과를 상세히 정리한 위키 문서를 팀원들과 공유함으로써, 성급한 도입으로 인한 부작용을 사전에 철저히 차단하고 시스템의 안정성을 해치지 않도록 지속적으로 관리하고 있습니다.

### [실무/프로젝트 문제 해결 경험]
AI 기반의 면접 평가 서비스 프로젝트에서 멘티의 음성 데이터(WAV 파일)를 분석하여 감정 및 텍스트를 추출하는 대용량 AI 분석 파이프라인을 비동기로 최적화한 경험이 있습니다. 초기에 오디오 파일이 업로드되면 백엔드 서버가 동기적으로 AI 모델 API를 호출하여 결과를 대기하는 방식으로 구현했으나, 파일의 크기가 클 경우 백엔드 서버에 타임아웃이 나고 오디오 스트림 처리가 끊기는 병목 현상이 발생했습니다. 이 문제를 해결하기 위해 Celery와 RabbitMQ 기반의 비동기 메시지 큐 아키텍처를 전격 도입했습니다. 사용자가 음성을 업로드하면 백엔드는 즉시 작업 ID를 반환하고, 오디오 원천 파일은 S3에 저장한 후 Celery 워커가 메시지를 수신하여 비동기적으로 Whisper와 감정 분석 모델을 병렬 처리하도록 구조를 이원화했습니다. 또한, 분석 진행 상황을 클라이언트가 실시간으로 폴링할 수 있도록 Redis에 작업 상태를 캐싱하는 데이터 레이어를 추가했습니다. 이를 통해 백엔드 서버의 커넥션 점유 시간을 제로로 만들었고, 병렬 분석 처리를 도입하여 분석 완료 대기 시간을 이전 동기식 대비 약 60% 이상 줄였습니다.

## 3. 🎙️ 질문 및 답변 대본

### ❓ [공통 질문 1]
* **질문**: "각자 프로젝트에서 주력 백엔드 기술과 인프라 컴포넌트를 선택할 때, 다른 대안 대신 해당 기술을 사용하기로 결정한 핵심적인 아키텍처적 이유는 무엇인가요?"
* **답변**:
 > "네, 저는 AI 파이프라인 처리를 위해서 파이썬 환경의 AI 모델들과 라이브러리 연동성이 우수한 FastAPI를 주력 기술로 선택했습니다. 대안으로 Django나 Flask도 있지만 비동기 웹소켓과 코루틴 지원이 뛰어난 FastAPI가 모델 추론 대기 환경에 적합하다고 보았습니다. 또한 AI 연산 특성상 단일 서버에서 동기적으로 처리하면 다른 일반 API 응답까지 끊기게 되기 때문에 비동기 메시지 브로커로 Celery와 RabbitMQ를 결합해 무거운 연산을 비동기 태스크 큐로 분리하는 설계를 구축했습니다."

### ❓ [공통 질문 2]
* **질문**: "프로덕션 서버를 실제로 운영한다고 가정했을 때, 실시간으로 발생하는 시스템 장애나 성능 병목을 감지하고 신속하게 원인을 파악하기 위해 어떤 모니터링 메트릭 수집 및 알림 체계를 구축할 것인지 각자의 직무 세부 분야 관점에서 말씀해 주세요."
* **답변**:
 > "AI 파이프라인에서는 CPU와 GPU의 하드웨어 리소스 사용량 및 Celery 워커의 동작 메트릭이 중요합니다. 저는 Celery 대시보드 도구인 Flower를 띄워 실시간 작업 실패율과 태스크 소요 시간을 확인하겠습니다. 또한 RabbitMQ 매니지먼트 플러그인을 활용하여 큐에 쌓인 메시지 수가 너무 늘어나는 병목 상황을 모니터링하겠습니다. 만약 특정 임계치를 넘는 경우에 알림을 연동하는 방식을 채택하고자 합니다."

### ❓ [개인 질문 1 (추천 1번)]
* **질문**: "대용량 WAV 파일 분석을 동기식 API 호출에서 Celery와 RabbitMQ를 활용한 비동기 작업 처리로 전환하셨는데, 태스크 유실 방지를 위해 RabbitMQ의 메시지 영속화와 Celery의 수동 Acknowledgment 설정을 어떻게 하셨나요?"
* **답변**:
 > "RabbitMQ에서 메시지가 유실되지 않도록 큐를 생성할 때 durable 옵션을 true로 설정하고, 퍼블리셔가 전송할 때도 delivery_mode를 2로 지정해 디스크에 기록하도록 처리했습니다. 또한 Celery 설정에서는 기본 자동 ack 정책 대신, 비즈니스 로직 연산이 완전하게 끝나 정상 반환되었을 때만 RabbitMQ로 ACK 신호를 전송하도록 task_acks_late를 true로 활성화했습니다. 다만 이 설정을 켜면 처리 중 워커 장애 발생 시 메시지가 다시 큐로 돌아가 중복 실행될 위험이 있으므로, 데이터베이스 저장 단에 유니크 키 제약을 두어 멱등성을 지키도록 보완했습니다."

### ❓ [개인 질문 2 (추가 질문)]
* **질문**: "데이터 전처리 과정에서 대용량 파일 업로드 시 발생할 수 있는 메모리 부족 문제를 예방하고 메모리 효율적으로 데이터를 파싱하는 전략은 무엇인가요?"
* **답변**:
 > "대용량 오디오나 비디오 파일을 통째로 메모리에 로드하는 것은 매우 위험하므로, FastAPI에서 클라이언트의 파일 업로드 수신 시 UploadFile을 사용해 백그라운드에서 임시 디렉토리에 spooled 파일로 나누어 스트리밍 쓰기를 수행하도록 구현했습니다. 전처리 시 Pandas 라이브러리를 사용해 데이터를 파싱할 때도 대형 파일은 memory_limit에 걸리기 쉽기 때문에, read_csv나 parser 등에서 chunksize 옵션을 명시해 5,000행씩 데이터를 루프로 잘라서 읽어 들였고, 이를 bulk insert 쿼리로 DB에 분할 삽입하여 단시간 내 메모리 점유율이 튀는 현상을 안정적으로 방어했습니다."
